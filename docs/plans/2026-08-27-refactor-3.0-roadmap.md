# AEPython 3.0 整体改进计划（Roadmap）

> **说明：** 本文档是 3.0 重构的总纲（roadmap + 设计决策）。它覆盖多个独立子系统，
> 每个工作流（W1–W7）开工时，再按 `superpowers:writing-plans` 的格式为该工作流单独
> 编写细粒度 TDD 实施计划（存放于 `docs/plans/`）。不要试图按本文档直接逐行施工。

**目标：** 在保持 `ae.*` 用户 API 兼容的前提下，把 2.0 的"字符串拼代码"桥接改为数据化协议，
修完已知的正确性缺陷，把构建、打包、Python 版本管理做成可移植可升级的工程。

**基线：** `2.0.0b2`（commit `2d8ef38`）+ UTF-8 修复（`d3e0ff5`）+ macOS 移植
（`origin/2.0.0b2` 三个提交：C++ 源码 #ifdef 分支、jsx/qtae 适配、`Mac/` Xcode 工程与
build/install 脚本，arm64、目标 AE 2026）。均已合入 `refactor/3.0`。

**技术栈：** C++17 / AE SDK 25.6 / pybind11 / 嵌入式 CPython 3.11（评估 3.12+）/ PySide6 / ExtendScript (ES3)。
Windows: v143 + vcxproj；macOS: Xcode 工程（`Mac/AEPython.xcodeproj`）。

---

## 全局约束

- **用户 API 兼容**：`import AEPython as ae` 与现有 `ae.app...`、`executeScript()`、
  `Python.exec/eval/execFile/import`（jsx 侧）的公开行为不破坏；内部协议可以完全换。
- **编码统一 UTF-8**：Python↔C++↔ES 全链路 UTF-8（`AEGP_ExecuteScript` 用
  `platform_encodingB=false`）；`CP_ACP` 仅允许出现在明确注释过的 ANSI-only API 边界
  （目前只有 `AEGP_StartUndoGroup`）。
- **平台**：Windows x64（AE CC2024+，v143，Windows SDK 10.0.26100）+ macOS arm64（AE 2026，Xcode）。
  平台差异一律走 `AE_OS_WIN` / `AE_OS_MAC` `#ifdef` 分支，新代码默认双平台可编译。
- **jsx 侧语言水平**：ES3（ExtendScript），不可用 JSON.parse 原生对象（需打包 json2）。
- **版本号**：3.0 系列从 `3.0.0a1` 开始，PiPL/`ae.__version__`/安装包三处一致。

## W1 桥接协议重构（数据传递）——核心工作流

**现状问题**：双向都是"拼接源码字符串 + eval"。转义在两侧十几处各自为政
（Python 用 `repr()`，jsx 手写 replace，属性名/模块名完全不转义），图层名带引号即炸；
返回值靠 `startswith('raise ')`、`rindex(",")` 这类字符串嗅探解析。

**目标设计**：

- 每侧收敛为一个调度入口：
  - ES 侧：`__AEPython_dispatch(requestJson) -> responseJson`
  - Python 侧：`_dispatch(request: dict) -> dict`（供 jsx→py 方向）
- 请求/响应为 JSON。操作集：`get` / `set` / `call` / `new` / `delitem` / `del` / `eval_raw`
  （`eval_raw` 保留任意代码执行能力，作为兼容后门与高级用法）。
- 对象句柄以标记对象编码：`{"$es": 17}`、`{"$py": 4}`；基本类型直接映射；
  `Infinity/NaN` 显式处理（JSON 不支持 → 用 `{"$num": "inf"}` 标记）。
- jsx 打包 `json2.js`（ES3 兼容）进 `AEPython.jsx`；Python 侧用标准 `json`。
- **转义只存在于 JSON 序列化一层**，删除 `repr()` 拼接与 jsx 手写 replace。
- 协议版本握手：init 时 jsx ↔ dll 各报协议版本，不匹配弹一次错误说明（防新旧混装）。
- 兼容层：`ae.executeScript(es_code)` 保留，内部走 `eval_raw`。

**连带修复（本工作流内消灭）**：jsx `PyObject.setattr` 缺引号（现在整个功能是坏的）、
`file.exist`→`exists`、`replace("\\","/")` 只换首个、`Python.import` 模块名注入。

**验收**：图层名/文本含 `"` `'` `\n` `\` 中日文 emoji 的 round-trip 测试全绿；
2.0 的 `tests/test_AEPython.py` 在兼容层上不改仍然通过。

## W2 C++ 层健壮性

- `executeScript`：`ERR` 短路后 `res`/`error` 为 NULL 的崩溃路径修复
  （NULL 保护 + `err != A_Err_NONE` 时抛带错误码的 Python 异常）；
  `strErr` 文本透传进异常信息（现在被丢弃，"忘装 jsx"场景无法自诊断）。
- `executeScript` 签名 `std::wstring` → `std::string`（UTF-8 直通，删 `toString/toWString` 两次转换；
  `getPluginPath` 保留宽字符，`startUndoGroup` 保留宽→ACP 一跳）。
- **DLL 边界改 C ABI**：`AEPython::exec/eval` 等改为 `extern "C"` + UTF-8 `char*` +
  显式 `AEPython_free()`（或两工程统一 `/MD`——二选一，倾向 C ABI，彻底消掉跨 CRT 堆风险）。
- `ESFreeMem` 的 `delete`→`delete[]`；`ESMallocMem`/`ESFreeMem` 分配器统一为 malloc/free。
- 生命周期：`AEGP_RegisterDeathHook` 注册退出钩子，按序销毁 Qt → interpreter；
  `AEPython::init` 全程 try/catch，失败用 `AEGP_ReportInfoUnicode` 报告并优雅禁用，不再崩 AE 启动。
- `InitPython` 的 PATH 操作改 `GetEnvironmentVariableW/SetEnvironmentVariableW`；
  `AEGP_ReportInfo` → `AEGP_ReportInfoUnicode`（UtilitySuite6）。
- `GetModuleHandle("AEPython.aex")` 硬编码 → `GetModuleHandleEx(GET_MODULE_HANDLE_EX_FLAG_FROM_ADDRESS)`
  （mac 侧已用 `dladdr` 等价实现，Windows 对齐）。
- macOS：`ReportInfoUnicode`/W-API 等 Windows 专属改动全部收在 `AE_OS_WIN` 分支内；
  mac 的 UTF-8 转换已在前置事项修复，W2 中补 mac 侧 `executeScript` 行为核对（实机）。

## W3 Python API 层（ae.py）

- `Array`/`Collection` 迭代器改生成器（消灭共享 `_i` 的嵌套遍历 bug）。
- `ESFunction/ESObjectFunction.__call__` 收到 kwargs 时显式 `TypeError`（现在静默丢弃）。
- `ESWrapper.__hash__ = lambda self: hash(self._es_id)`（现在定义了 `__eq__` 导致不可哈希）。
- `_create_ESWrapper`：`eval(class_name)` → `globals()` 查表；
  `__ES_class_names` 白名单改为 `__init_subclass__` 自动注册，消除双份维护。
- `float('inf')/nan` → ES `Infinity/NaN` 映射（W1 协议层自然解决，此处留回归测试）。
- 公开 API 补类型注解与 docstring（对齐 ae-scripting 文档链接）。
- 性能：新增 `ae.batch()` 上下文管理器（块内调用合并为一次 ES 执行）；
  文档明确"每次属性访问=一次 ExecuteScript"的成本模型。热路径原生化（AEGP suite 直调）
  列为 3.x 后续，不进 3.0。

## W4 UI（qtae）

- **惰性加载**：AE 启动时不 import PySide6/不建窗口（现状在 `EntryPointFunc` 里全做了，
  拖慢 AE 启动且有 Qt DLL 冲突面）；首次打开 Python 窗口才初始化，菜单命令处加载。
- `Logger` 不再继承 `logging.Handler`（改纯 file-like）；输出区设
  `document().setMaximumBlockCount()` 上限，防止长会话内存无限涨。
- Python 窗口体验：代码区行号 + 基础高亮（`QPlainTextEdit` + `QSyntaxHighlighter`，
  不引第三方编辑器组件，YAGNI）、Ctrl+Enter 执行、输入历史（上下键）、字体可配。
- 主题跟随 AE 明暗（读 prefs 的 brightness 值），替换现在写死的 `#444444` 样式表。
- macOS 平价：当前 mac bootstrap 只 `import ae` 不加载 qtae（无 Python 窗口）。
  W4 内评估 mac 上的 PySide6 加载与窗口宿主方案（`getMainHWND` 对应物），
  做不到则明确 mac 3.0 以 `Python.exec`/ExtendScript 驱动为主并写入文档。

## W5 构建与包管理

- **SDK 路径解耦**：vcxproj 增加 `AE_SDK_ROOT` 属性（环境变量 fallback），
  include 路径改 `$(AE_SDK_ROOT)\Examples\Headers` 等，仓库放哪都能编，
  junction 技巧降级为"没设变量时的兼容方式"。（CMake 迁移列为可选后续，不阻塞 3.0。）
- pybind11 由整库 vendored 改 **git submodule**（锁 tag）；ExtendScript-Toolkit 两个头保留 vendored。
- aex/dll 嵌入 `VERSIONINFO` 资源（版本号由单一来源生成，见 W6 的 version.h）。
- `BuildScripts.ps1` 参数化：`-Version`、`-OutDir`、`-SkipPip`；产出 zip + SHA256 校验和文件；
  下载 python embed zip / get-pip.py 校验哈希。
- CI（GitHub Actions，仓库已迁 `ChenxingM/AEPython`）：
  - job1：Python 层 lint（ruff）+ W7 的 pytest（无 AE 依赖，直接可跑）。
  - job2：C++ 编译。AE SDK 不能进公开仓库——用 private submodule 或 Actions secret
    拉取 SDK zip（许可合规，文档注明）。产物 artifact 上传。
- 开发环境文档 `docs/BUILDING.md`：SDK 放置、`AE_SDK_ROOT`、worktree 下构建需为该
  worktree 另建 SDK junction（或直接用 `AE_SDK_ROOT` 后无此问题）、NuGet restore、部署路径；
  macOS 章节：Xcode 工程、`Mac/build.sh`（arm64）/`install.sh`、codesign 说明。
- macOS 打包：`BuildScripts` 的 mac 对应物（bundle + Scripts + zip）；CI 的 macos runner job
  排在 Windows job 之后做，SDK 分发方式同上。

## W6 Python 版本管理

- **运行时发现**：C++ 不再硬编码 `python-3.11.9-embed-amd64`——启动时 glob
  `python-*-embed-*` 目录（多个时取版本最高），或读同目录 `AEPython.ini` 的显式指定。
  升级 Python 不再需要重编 C++。
- **单一版本源**：新增 `version.h.in`/`version.py` 生成机制，插件版本 + Python 版本号
  只写一处（现状散布 4 处：BuildScripts.ps1 / packages.config / vcxproj props 路径 / C++ 硬编码）。
- **升级评估**：3.11 → 3.12/3.13（pybind11 兼容性、PySide6 对应版本、`Py_LIMITED_API` 是否
  值得启用以解耦小版本）。3.0 目标：保持 3.11 出厂，但升级只改配置不改代码。
- 依赖锁定：`requirements.txt` 加 `--require-hashes` 锁文件（或 uv 导出）；
  可选 `Scripts/site/` 用户扩展目录加入 sys.path，TA 装包不污染发布目录。
- **macOS Python 内嵌方式（开放问题）**：查明 `Mac/AEPython.xcodeproj` 当前链接的是
  系统/Homebrew Python 还是内嵌 framework；3.0 目标与 Windows 对齐——随包分发、
  运行时发现、升级不重编（python.org macOS framework 或 python-build-standalone）。

## W7 测试与质量

- **transport 抽象**：`ae.py` 对 `_AEPython.executeScript` 的依赖收敛到一个可注入的
  transport 接口；提供 `FakeESTransport`（记录/回放 + 极简 ES 语义模拟），
  `ae.py` 逻辑用 pytest 脱离 AE 跑（这是 CI job1 的基础）。
- AE 内集成测试：恢复并扩充 `test_non_ascii_strings`（中日文/emoji/引号/换行 round-trip），
  加 W1 协议 round-trip 用例；`tests/run_in_ae.jsx` 一键在 AE 里跑全部并输出结果文件。
- 编码回归：CP932 系统下的全链路用例作为发布 checklist 固定项。

## 风险与决策记录

- **兼容风险**：`eval_raw` 后门保证极端用法可迁移；2.0 测试套在兼容层上原样通过是硬门槛。
- **C ABI vs /MD**：选 C ABI（彻底），若实施中发现改动面过大再降级为 /MD（半小时低风险）。
- **CMake**：明确不进 3.0（AE_SDK_ROOT 已解决可移植性主诉求），避免范围膨胀。
- **热路径 AEGP 原生化**：不进 3.0，等 `ae.batch()` 之后仍有性能诉求再立项。
- **CI 中的 AE SDK 分发**：受 Adobe 许可约束，只能走 private submodule / secret，
  文档中不得引导公开再分发。

## 执行方式

每个工作流开工时：
1. 用 `superpowers:writing-plans` 出该工作流的 TDD 实施计划（bite-sized 任务，含测试代码）；
2. 在 `refactor/3.0` 分支（本 worktree）实施，任务级提交；
3. 里程碑点合 alpha tag 并出安装 zip 供站内试用。
